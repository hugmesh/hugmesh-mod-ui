Recommend to an admin

Record an instance-block or user-removal recommendation into the federation queue. You recommend; an administrator decides — a moderator never removes directly.

Pick "instance-block" to recommend cutting off a whole remote server, or "user-removal" to recommend removing a single account. For an instance-block enter the server domain (e.g. evil.example); for a user-removal enter the full account (e.g. @user:instance.example). Required. Optional note for the deciding admin — a short justification such as "spam" or "abuse". {{ recommendError() }} {{ recommendNote() }}

Ban / lift access

Ban a user from a platform-access role. You cannot ban yourself or a moderator/administrator (the server enforces this; a rejected attempt is announced below). The effect is applied asynchronously by the reconcile loop.

Which access the ban removes: "matrix" or "mastodon" social login, or "profile" for the user's profile/account role. The user to ban or lift — a local username or a full @user:instance.example address. The same target is used by both Ban and Lift ban. Required. Leave blank for a permanent ban; a positive value auto-restores access after that many seconds. Optional reason recorded in the audit trail (e.g. "abuse"). "Ban" applies the ban above; "Lift ban" restores access for the same target user and platform. Both take effect asynchronously and are reported below. {{ banError() }} {{ banNote() }}

Domain-lock (force local-only)

Force a user local-only on Matrix or Mastodon — they keep their access but their traffic stops federating. This is an additive marker; remove it to restore federation. You cannot domain-lock yourself or a privileged user.

The platform on which the user is forced local-only — their posts stop federating there but they keep their account. The user to lock or unlock — a local username or full @user:instance.example address. The same target is used by both Domain-lock and Remove lock. Required. Optional reason recorded in the audit trail (e.g. "evasion"). "Domain-lock" adds the local-only marker; "Remove lock" clears it to restore federation. Both take effect asynchronously and are reported below. {{ domainLockError() }} {{ domainLockNote() }}

Server-wide block

Apply a server-wide block on Matrix or Mastodon, against a single user or a whole remote instance. This calls the platform's homeserver admin and is always recorded in the audit trail below.

The network the block applies to: Matrix or Mastodon. "user" blocks one account; "instance" blocks an entire remote server and everyone on it. For a user scope enter the full account (e.g. @user:instance.example); for an instance scope enter the server domain (e.g. instance.example). Required. Optional reason recorded in the audit trail (e.g. "abuse"). {{ blockError() }} {{ blockNote() }}

Administrator-only actions

These actions have no moderator endpoint — they are shown here so the boundary is explicit. Each is disabled but keeps keyboard focus so the reason is read out.

  • Granting or revoking a role is not a moderator action and has no endpoint — role assignment is handled by an administrator through the identity provider.
  • Granting external-client (Matrix/Mastodon app) access is an administrator action with no moderator endpoint — users manage their own connected apps in their account.
